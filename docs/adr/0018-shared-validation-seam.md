# 0018. Share one validation seam across layers, in two phases

Status: Accepted
Date: 2026-10-20

## Context

Validation isn't only an API concern. Domain code, ORM changesets and form
handling validate too, and some rules need services ("this email isn't
taken"). If each layer has its own result shape, errors can't be mapped
consistently to responses.

## Decision

- **One result shape**: a list of field errors, each with a path (JSON
  Pointer), a stable code, parameters and a message key for translation. It
  maps into the error model and problem+json automatically.
- **Two phases**: **shape** validation is pure and synchronous (types,
  ranges, formats, cross-field rules) and is read from struct tags at boot,
  or will be generated by Themis; **semantic** validation gets a `context`
  and can use a read transaction.
- Generated and hand-written rules are to compose in a defined order.

## Consequences

- Every layer reports validation failures the same way, and clients see one
  error format.
- Themis can generate matching client-side validators.

## Alternatives considered

- **API-only validation.** Leaves domain and form validation to diverge.
